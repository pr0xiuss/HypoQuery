Section 1 — Project Overview
HypoQuery
Project Summary

HypoQuery is an Enterprise PostgreSQL Workload Intelligence Platform.

It is not a simple SQL query optimizer.

It is not an AI chatbot.

It is not an admin dashboard.

Instead, it is a complete SaaS platform that continuously analyzes PostgreSQL databases, discovers performance issues, explains why they occur, recommends deterministic optimizations, validates those recommendations, stores operational knowledge, and presents everything through a modern enterprise web application.

The AI component is intentionally small.

AI is used only to explain deterministic findings in natural language.

The optimization engine itself is deterministic.

The backend is the source of truth.

Product Vision

Imagine something between

Datadog
New Relic
pgAdmin
PlanetScale Insights
Azure Database Advisor

combined into one product specifically focused on PostgreSQL optimization.

The product should feel like enterprise software rather than a student project.

Primary Goal

Help engineering teams answer questions like

Why is my database slow?
Which queries should I optimize first?
Which indexes are missing?
Which indexes are unused?
Why did performance regress yesterday?
Which optimization will save the most time?
Is this recommendation actually safe?
How healthy is my database?

Everything should be discoverable through dashboards instead of manually inspecting PostgreSQL.

Backend Design Principles

The frontend should assume the following.

Passwords are write-only

Passwords are accepted during creation.

Passwords are never returned.

Never attempt to display them.

UUIDs identify everything

Section 10 — Critical Engineering Constraints & Final Instructions

This section contains the most important implementation rules.

The frontend AI should follow these throughout development.

1. Do Not Invent Backend APIs

Only consume APIs that currently exist.

If an API is missing,

create the UI,

mock the state if necessary,

but clearly isolate it so it can later connect to the real backend.

Never assume backend behavior.

2. Respect Backend Architecture

Business logic belongs to the backend.

Examples

Correct

Refresh Metadata

↓

Backend performs discovery

↓

Frontend displays result

Incorrect

Frontend discovers tables

Frontend calculates metadata

Frontend stores database information

The frontend should never duplicate backend responsibilities.

3. Keep Components Generic

Do not build

OrganizationTable

ProjectTable

EnvironmentTable

as completely separate implementations.

Instead create reusable building blocks.

Example

DataTable

StatusBadge

SummaryCard

DetailCard

SearchBar

PageHeader

EmptyState

Compose pages using these reusable components.

4. Design Once

Many pages are currently placeholders.

Do not redesign navigation when new modules arrive.

Instead

build the navigation now,

enable menu items later.

5. Enterprise Quality

This project is intended to serve as a portfolio-quality enterprise application.

The UI should feel production-ready.

Avoid

Huge gradients

Random colors

Inconsistent spacing

Oversized animations

Use restrained, professional styling.

6. Consistency Over Creativity

A consistent application is more valuable than highly customized pages.

Every page should follow the same layout pattern.

Example

Header

↓

Breadcrumb

↓

Summary Cards

↓

Primary Content

↓

Secondary Actions

Users should quickly learn how the application behaves.

7. Performance

Use

Lazy loaded routes
React Query caching
Memoization where appropriate
Pagination-ready tables
Efficient re-rendering

Do not optimize prematurely, but avoid obvious inefficiencies.

8. Error Recovery

Every page should gracefully handle

Loading

No Data

Validation Errors

Network Failure

Server Errors

Permission Errors

Always provide a path forward for the user.

9. Code Quality

The finished frontend should resemble something maintained by a professional engineering team.

Prioritize

Small components

Clear naming

Consistent file organization

Reusable hooks

Reusable services

Predictable state

Readable code

Avoid unnecessary abstractions.

Final Note to the Frontend AI

HypoQuery is not just another CRUD application.

It is an Enterprise PostgreSQL Workload Intelligence Platform built with a backend-first architecture.

The backend has been carefully designed through multiple architectural phases, and the frontend's responsibility is to expose those capabilities through a clean, scalable, and professional user experience.

When making implementation decisions, prefer maintainability, consistency, and extensibility over shortcuts. Build reusable components, keep business logic in the backend, and design the UI so future optimization, AI, analytics, and observability modules can be integrated without major redesign.

The objective is to create a frontend that feels like a polished enterprise SaaS product from day one, even though only the platform foundation has been implemented so far.
